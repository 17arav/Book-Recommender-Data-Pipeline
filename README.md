# Book Recommender: End-to-End Collaborative Filtering System

## Overview
This repository contains a complete, end-to-end User-Based Collaborative Filtering Book Recommender System. The objective of this project was twofold: 
1. **Data Engineering:** Ingest raw, messy datasets (Users, Books, and Ratings), perform rigorous data cleaning, resolve ID mismatches, and transform the data into a highly compressed Sparse Matrix.
2. **Machine Learning:** Build a custom mathematical recommendation engine from scratch that calculates user similarity, predicts personalized book ratings, filters out edge cases, and outputs clean, actionable recommendations.

## Datasets Handled
The raw, unprocessed datasets used for this project were sourced from Kaggle: **[Book-Crossing Dataset](https://www.kaggle.com/datasets/somnambwl/bookcrossing-dataset?resource=download)**. 
The raw data includes:
1. **Users.csv:** Contains user demographics (Age).
2. **Books.csv:** Contains book metadata (ISBN, Title, Author, Year, Publisher).
3. **Ratings.csv:** Contains user-book interactions on a scale of 0 to 10.

**Engineered Data & Outputs:**
The fully cleaned, machine-learning-ready files generated by this pipeline are included directly in this repository:
* `Master_Dataset.csv`: The consolidated, ID-corrected, and normalized dataset.
* `Recommender_Matrix.libsvm`: The final Compressed Sparse Row (CSR) matrix, optimized for immediate algorithmic ingestion.
* `20_Users_Recommendations.csv`: The final system output, containing the top 5 predicted book recommendations for a batch of 20 target users.

## Phase 1: Data Engineering & Matrix Construction

### 1. Data Cleaning & Imputation
* **Age Normalization:** Filtered out impossible user ages (under 5 or over 100). Imputed missing and invalid ages with the calculated mean of valid users (~35 years old).
* **Metadata Scrubbing:** Dropped books missing critical metadata (Title, Author, Publisher).
* **Year Correction:** Filtered out impossible publication years (e.g., year 0 or 2050). Imputed invalid years with the median valid year (1994).
* **Rating Normalization:** Identified out-of-bounds ratings (>10 or <0) and replaced them with the rounded mean of valid ratings to prevent skewing the algorithm.

### 2. ID Translation & "Ghost Data" Handling
The raw datasets utilized alphanumeric ISBNs and disjointed User IDs, which are incompatible with matrix indices.
* Created a translation dictionary to map all original IDs to sequential integers.
* **Handling "Ghosts":** Ratings from users or for books that did not exist in the master profiles were intentionally kept to preserve mathematical relationships for the collaborative filtering algorithm. They were assigned sequential IDs appended to the end of the dictionaries.

### 3. Sparse Matrix Construction (CSR)
* Merged the cleaned tables into a single `Master_Dataset.csv`, sorted strictly by `UserID`.
* Transformed the 55+ billion potential data points into a Compressed Sparse Row (`csr_matrix`) using `scipy.sparse`. This method ignores zeroes (unread books), drastically reducing memory overhead while optimizing for machine learning models that read data row-by-row.
* Exported the final CSR matrix into the highly compressed `libsvm` format using `sklearn`.

## Phase 2: The Recommendation Engine

To generate personalized predictions, a custom 6-step User-Based Collaborative Filtering pipeline was developed to run efficiently on top of the Sparse Matrix:

### 1. Mathematical Similarity (The Matchmaker)
Calculates the exact **Cosine Similarity** between a target user and all other users in the dataset. Because the data is highly sparse, the algorithm utilizes `scipy.sparse` fast vector math (dot products and matrix transpositions) rather than standard NumPy arrays to prevent memory crashes.

### 2. Neighborhood Selection (The "Data Twins")
Sorts the similarity scores and isolates the top *k* nearest neighbors whose historical reading habits mathematically align the closest with the target user.

### 3. Candidate Filtering
Cross-references the neighbors' highly-rated reading histories against the target user's history, dynamically stripping out any books the target user has already read.

### 4. Rating Prediction 
Calculates a predicted rating for every unread candidate book using a weighted average. The algorithm is weighted so that the opinions of highly similar neighbors (e.g., 99% match) carry significantly more mathematical weight than lower-tier neighbors.

### 5. Ranking & The "Ghost Filter"
Sorts the predicted scores to isolate the top highest-scoring Book IDs. The system features a built-in **Ghost Filter** that catches anomalies where an ID exists but the string title is missing (`NaN`). The filter skips these broken records and pulls backup books until it secures exactly 5 real, human-readable recommendations.

### 6. Batch Processing & Export
The 6 modular functions are wrapped in a master execution loop that can accept any number of target users. The final output—containing the `User_ID`, `Book_ID`, `Book_Title`, and `Recommendation_Score`—is compiled into a Pandas DataFrame and exported as a CSV dashboard for final review. If a user lacks sufficient reading history for the algorithm to find neighbors, the system safely logs "Not enough data to recommend."
